# 미션 Phase C — 인계장 픽업(차 밑 진입 + 축 감지 + 리프트) 설계

> 작성: 2026-07-25. 선행: Phase A(4카메라), Phase B(도크→XN 융합주행, merge-ready),
> 회전 기구학 재보정(k=+1.10). 상위: `2026-07-24-mission-e2e-design.md` §1.
> UI 실행 필수. 진행·디버깅은 HANDOFF.md / DEBUG_LOG.md.

## 1. 목표

입차팀 로봇 2대가 인계장 파란 베이에 놓인 **Pickup** 밑으로 차례로 진입해, **측면 뎁스캠으로
바퀴를 실시간 감지**(위치를 미리 계산·기억하지 않음)하고 각각 앞축·뒤축 중심에서 정지한 뒤
**리프트로 차를 들어올린다**. 운반·주차는 Phase D.

## 2. 사용자 확정 사항

| 항목 | 결정 |
|---|---|
| 인계장 | **파란 베이**(입차 방향 쪽) = `handoff_bay_OUT` 패드, 마커 **W_OUT(id 51)**, 월드 (x=-8.5, z=+7.075), 패드 **6.4 × 3.2 m** |
| 차량 | **Pickup** (실측 전장 **5.83 m** × 폭 1.91 m, 축거 3.594 m, 타이어반경 0.423 m) |
| 차량 자세 | 베이 **긴 변(x축)** 방향으로 눕힘(5.83 < 6.4). 차 앞이 게이트 쪽, 뒤가 주차칸 쪽 |
| 로봇 진입 방향 | **주차칸 쪽 끝**에서 차 밑으로 진입(-x 방향 주행) |
| 역할 | **entry_follow = 앞축**(먼저 진입, 더 깊이) / **entry_lead = 뒤축**(나중 진입) |

## 3. 선행 자산 — p4_depth 브랜치(이식 대상)

`origin/p4_depth`에 **이미 검증된 구현**이 있다. Phase C는 신규 개발이 아니라 **v4 미션으로 이식**이다.

- `isaacpjt/Isaac_envo/depth_stop_detector.py` — 순수 numpy. `roi_min_depth(depth_hw, roi_frac)`,
  `DepthStopDetector(baseline_frames=30, drop_margin=0.05, confirm_frames=3).update(step, roi)`.
  ROI 최소뎁스가 **학습된 baseline − drop_margin** 아래로 연속 프레임 떨어지면 트리거.
- `isaacpjt/Isaac_envo/depth_stop_lift_test_dual.py` — 로봇 2대가 **같은 중심선을 한 줄로** 진입해
  각자 **좌측 사이드 뎁스캠**으로 바퀴를 감지, **트로프 진입/이탈 중간값**으로 축 중심에 정렬 후
  앞축·뒤축 동시 리프트. **기본 차량 Pickup**, 10개 차종 전부 동작, **축 중심 오차 실측 14 mm**.
  더 먼 목표(앞축) 로봇이 앞서 들어간다(뒷축 로봇이 먼저 멈춘 자리를 앞축 로봇이 지날 수 없으므로).
- 핵심 원리: 바퀴는 곡면이라 **최솟값 위치 ≠ 축 중심**이다. 진입/이탈의 **중간값**은 대칭 기하만으로
  차종별 보정값 없이 축 중심에 수렴한다.
- 리프트: `ARM_TARGETS = {arm_left_front_joint: +90, arm_left_rear_joint: -90,
  arm_right_front_joint: -90, arm_right_rear_joint: +90}` (deg) 를 램프로 전개.

**이식 시 달라지는 점**: 주차장(v4), 로봇 자산(`hwia_4cam_mecha_roller_lowered.usd`), 접근 방식
(GT 텔레포트가 아니라 **Phase B 융합주행의 연장**), 진입 축(v4 베이는 x축), 차량 배치(파란 베이).

## 4. 안무 (Phase B 종료 지점에서 이어짐)

Phase B 종료 상태: 두 로봇이 XN 남쪽에 입차 방향을 보고 정렬(entry_follow는 XN 축선, entry_lead는
옆으로 비켜선 대기 위치).

1. **BAY_APPROACH** — 두 로봇이 베이 진입선(패드의 주차칸 쪽 끝 바깥)으로 융합주행. 마커는 W_OUT(51)
   을 쓰되 차가 마커를 가리면 XN 기준 + 오도로 접근하고, 최종 정밀은 뎁스 감지가 맡는다.
2. **TURN** — 차 길이 방향(-x)으로 **90° 제자리 회전**(재보정된 기구학으로 정확).
3. **INGRESS_FRONT** — **entry_follow가 먼저** 차 밑으로 진입. 좌측 뎁스캠 ROI 최소뎁스 스트림을
   `DepthStopDetector`에 넣어 **앞축 바퀴의 트로프 진입/이탈**을 잡고 **중간값으로 정렬 정지**.
4. **INGRESS_REAR** — **둘째 바퀴(뒤축) 감지 시점에 맞춰 entry_lead 진입**, 같은 방식으로 뒤축 중심 정지.
5. **LIFT** — 두 로봇이 각각 swing arm 4개를 전개해 앞축·뒤축을 들어올린다. 차량 휠 높이 상승으로 판정.

## 5. 수용 기준

- `--mission=C`(또는 B 연장)로 두 로봇이 **바퀴 위치를 미리 계산하지 않고** 뎁스 감지만으로 각각
  앞축·뒤축 중심에 정지한다(축 중심 오차 목표: p4_depth 실적 14 mm 수준, 상한 5 cm).
- 리프트 후 **차량이 실제로 들린다**(휠 상승 판정, p4_depth/기존 리프트 테스트 기준 재사용).
- 제어는 **GT 없이**(융합측위 + 뎁스 감지). GT는 채점·기록 전용.
- 기존 `--mission=B` 및 `--probe=FUSE/M5/REAR/REARXN/ROTCHK*` 회귀 없음. **GUI 실행 가능**.

## 6. 알려진 리스크

- **헤딩 정확도 ~5.5°**: 차 밑 진입은 폭 여유가 작다(로봇 폭 0.73 m vs 트럭 윤거 1.641 m). 진입 전
  정렬이 부족하면 바퀴/차체와 간섭할 수 있다 → 필요 시 진입 직전 마커 재정렬 또는 뎁스 기반 횡보정.
- **마커 근거리 사각(<1.1 m)**: 베이 앞에서 W_OUT이 차에 가려지거나 너무 가까우면 못 본다 →
  접근은 마커, 최종은 뎁스라는 역할 분담을 명확히 한다.
- **차량 물리 불안정**: 휠 충돌체가 Cylinder라 PhysX에서 진동한다(HANDOFF 기록). p4_depth/리프트
  테스트가 쓰던 `--sphere-wheels` 등 완화책을 그대로 가져올지 Task 1에서 판단한다.
- **베이 여유**: 패드 6.4 m에 차 5.83 m → 앞뒤 여유 0.57 m. 진입로 쪽 여유가 작으니 로봇 진입
  시작점은 패드 밖에서 잡는다.
