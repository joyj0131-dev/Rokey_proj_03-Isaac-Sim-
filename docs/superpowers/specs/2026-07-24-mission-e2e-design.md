# v4 2로봇 입차 E2E 미션 — 설계 (개요 + Phase A)

> 작성: 2026-07-24. 선행: ArUco 측위/융합 스펙(2026-07-24-aruco-marker-localization-v4-design.md, 부록 A~E),
> p4_depth 브랜치(뎁스캠 바퀴감지). UI 실행 필수. 진행·디버깅은 HANDOFF.md / DEBUG_LOG.md 에 기록.

## 1. 미션 개요 (전체 E2E, 사용자 시나리오)

입차팀 로봇 2대가 도크에서 나와 마커로 주행, 인계장의 차를 앞/뒤 축을 잡아 들어 올려 운반,
목표 주차칸에 넣는다. **GT 를 제어에 쓰지 않고 ArUco 마커(+휠 오도 융합, Phase 3 검증)로 주행·정렬**하며,
차 밑 진입 시 **바퀴 위치를 미리 계산하지 않고 측면 뎁스캠으로 실시간 감지**한다(p4_depth).

### 전체 흐름 (단계 분해)

| Phase | 내용 |
|---|---|
| **A. 로봇 카메라** | `cam_qr_down` 제거 + `cam_rear` 추가(front 미러, RGB ArUco) → 앞/뒤/좌/우 4개 |
| **B. 도크→인계장 주행** | 출발(z+) → 후방캠으로 **도크(서있던 곳) 마커 점검** → **제자리 90° 회전** → 인계장(주차장 안 파란 구역)으로 마커 융합 주행 |
| **C. 픽업** | 인계장 앞 마커 인식 → 전방캠 정렬 → 차 밑 진입 → **측면 뎁스캠 트로프-중간값으로 축 감지·정지** → 리프트. 앞/뒤 로봇 순차 |
| **D. 운반→주차** | 차 잡은 뒤 앞/뒤 로봇의 **차 안쪽 바닥 카메라(앞축=후방캠/뒤축=전방캠)** 로 정렬·운반 → 목표 마커 → 정렬·90°회전·재정렬 → 주차칸 진입 |

### 카메라 역할 (Phase A 이후 4대)

| 카메라 | 역할 |
|---|---|
| `cam_front` | RGB ArUco: 접근·정렬, 운반 중 뒤축 로봇의 차 안쪽 바닥 |
| `cam_rear`(신규) | RGB ArUco: 도크 마커 점검, 운반 중 앞축 로봇의 차 안쪽 바닥 |
| `cam_side_left/right` | Depth: **바퀴 감지(p4_depth)** — 차 밑 진입 시 옆에서 바퀴를 봄 |

### 바퀴 감지 (p4_depth, Phase C 에서 통합)

`depth_stop_detector.py`(순수 numpy): ROI 최소뎁스가 **학습된 baseline − margin** 아래로 연속 프레임
떨어지면 바퀴 진입. 측면 뎁스캠으로 바퀴가 시야에 들어왔다 나가는 **트로프(골)의 진입·이탈 중간값 =
축 중심**(바퀴 곡면이라 최솟값 위치 ≠ 축 중심, 대칭 통과 성질로 중간값을 씀). **미리 기억 안 함.**

### 인계장 재설계 (사용자, 2026-07-24)

주차장이 작아 인계장을 **주차장 안 파란색 구역**으로 옮긴다. 그 앞 ArUco 마커를 기준으로:
1. **나중에 차 밑 들어갈 로봇이 먼저** 나와 **후방캠**으로 그 마커를 인식하고 **x+ 방향으로 이동**.
2. 그다음 **먼저 차 밑 들어갈 로봇**이 나와 같은 마커를 **전방캠**으로 인식하고 차 밑으로 진입·파지.

(B/C 의 정확한 좌표·마커 id·순서는 각 Phase 착수 시 확정.)

### 공통 요구 (전 Phase)

- **UI(GUI) 실행 가능**해야 한다.
- 진행 상황·중요 디버깅은 **HANDOFF.md / DEBUG_LOG.md** 에 기록.
- 적용 개념은 **개념 md** 로 설명(이 문서 + 카메라/뎁스/융합 개념).

## 2. Phase A — 로봇 카메라 정리 (앞/뒤/좌/우 4대)

### 목표

로봇 에셋을 정확히 4개 카메라로 만든다: `cam_front`, **`cam_rear`(신규)**, `cam_side_left`, `cam_side_right`.
레거시 `cam_qr_down`(바닥 위 5cm, 시야 5.8cm 로 사용 불가)을 **제거**하고, `cam_rear` 를 `cam_front` 의
**미러**(뒤쪽 −X, 뒤+하향, 같은 높이·화각)로 **전방과 똑같이 에셋에 저작**한다.

### 왜

- 후방캠: 미션 B 의 도크 마커 점검, D 의 앞축 로봇 차 안쪽 바닥 정렬에 필요.
- 미션은 앞/뒤 대칭(앞축·뒤축 로봇)이라 전/후 카메라가 대칭이어야 한다.

### 구성 요소

1. **저작 스크립트** `isaacpjt/hwia_parking_robot_final_caster_package/build_rear_camera.py`
   - 입력: 기존 로봇 에셋(`hwia_depth_cam_mecha_roller_lowered.usd`, 러너가 쓰는 것).
   - `cam_front` 프림의 로컬 변환을 읽어, base_link 아래 `cam_rear_link` 를 **그 미러**로 저작(위치 X 부호 반전 + 수평 180° 회전으로 뒤를 보게, 하향 각·화각·intrinsics 동일).
   - `cam_qr_down` 관련 프림 제거.
   - 다른 카메라(side_left/right)·지오메트리·롤러·물리 미변경. 팀 원본 소스 미변경(새 4-카메라 변형본 저장).
   - 출력: `hwia_4cam_mecha_roller_lowered.usd`.
2. **러너 지원** `parking_v4_runner.py`
   - `ROBOT_USD` 를 4-카메라 변형본으로 전환.
   - `find_rear_camera(stage, robot_id)` 추가(`find_front_camera` 대칭 — 이름에 "rear" 포함 카메라 선택).
   - Phase A 스모크: 스폰 시 카메라 **정확히 4개**(front/rear/side_left/side_right, qr_down 없음) 검증 토큰.
3. **검증(후방캠 실동작)**
   - 후방 카메라를 OmniGraph 로 발행(`/robot_<id>/rear/image_raw` + camera_info), 로봇 **뒤에 마커를 두고** 외부 검출 노드(Probe A 방식)로 검출 확인. 전방과 대칭으로 동작함을 실측.
4. **문서**
   - 개념 md 는 이 스펙의 1절(카메라 역할·뎁스 바퀴감지)로 대체/확장. HANDOFF/DEBUG_LOG 에 Phase A 결과 기록.

### 수용 기준

- 러너 스폰 시 로봇 카메라가 **정확히 4개**(qr_down 없음, rear 있음).
- 후방 카메라가 로봇 뒤 마커를 검출(전방과 대칭). 스모크 통과.
- 기존 FUSE/M5(전방 카메라) 동작 회귀 없음(전방·측면 미변경).

### 범위 밖 (다음 Phase)

- B: 도크→인계장 주행 로직. C: 뎁스 바퀴감지 통합·리프트. D: 운반·주차. 인계장 파란 구역/마커 환경 변경.

### Phase B 선행 조건 (Phase A 최종 리뷰에서 도출, 2026-07-24)

Phase A 를 병합 가능 상태로 끝내면서, 다음 Phase 착수 전에 반드시 처리할 것들이 드러났다.

1. **`attach_camera_graph` 역할 파라미터화(차단성 — B/D 착수 전 필수).** 현재
   `attach_camera_graph(robot_id, cam_path)` 는 `robot_id` **하나로** ROS 네임스페이스
   (`/robot_<id>/image_raw`)와 OmniGraph 경로(`/Graphs/cam_<id>`)를 **둘 다** 만든다. 그래서
   한 로봇에 전방+후방 카메라를 **동시에 발행할 수 없다**(토픽·그래프 경로 충돌). Phase A 는
   `--probe=REAR` 를 `--cameras=0` 으로 돌려 회피했다. 하지만 B(출발→후방캠 도크점검→회전→
   전방캠 융합주행)와 D(전+후 카메라로 차 안쪽 정렬)는 **역할별 카메라가 동시에** 필요하다.
   → `attach_camera_graph(robot_id, cam_path, role)` 로 확장: 네임스페이스
   `/robot_<id>/<role>/image_raw`(스펙 2.3 의 원안), 그래프 경로 `/Graphs/cam_<id>_<role>`.
   검출 노드도 토픽 변경에 맞춰 조정.
2. **후방캠 근거리 사각(≥~1.1m)을 B 도크점검 트리거에 반영.** 후방 카메라는 ~1.1m 이상에서만
   마커를 검출한다(전방과 동일 한계). B 는 로봇이 도크(거리 0)에서 출발하며 후방캠으로 도크
   마커를 점검하므로, **점검 시작을 로봇이 ≥1.1m 벗어난 뒤로 지연**해야 한다.
3. **미션은 `parking_v4_runner.py` 위에 구축.** 정리된 4-카메라 자산을 쓰는 러너는 이것뿐이다.
   레거시 `dock_lift_handoff_runner*.py` 는 옛 8-카메라 자산을 참조하므로 미션에 쓰지 않는다.
4. (비차단, 후속) 러너 내 카메라 나열 스니펫 3중복 → `_robot_cameras()` 헬퍼로 통합(B 가 이 파일을
   손댈 때 함께). 대칭 주장 정밀화용 현 4-캠 자산 `--probe=A` 재측정도 B 에서 겸사.
