# 주차로봇 웹 UI 초보자 안내서

이 문서는 `feature/UI` 브랜치에 구현된 **주차로봇 통합 관제센터**를 처음 보는 사람도
쉽게 이해하고 테스트할 수 있도록 정리한 안내서입니다.

웹 UI 주소는 기본적으로 다음과 같습니다.

- 관제 화면: <http://127.0.0.1:8000>
- API 문서: <http://127.0.0.1:8000/docs>

---

## 1. 이 웹 UI로 무엇을 할 수 있나요?

웹 UI에서는 다음 작업을 할 수 있습니다.

1. 주차면 A1~A3의 빈자리와 점유 상태 확인
2. 입차 전용 로봇 2대와 출차 전용 로봇 2대의 상태·위치 확인
3. 차량번호를 입력해 입차 또는 출차 요청
4. 로봇이 차량에 접근하고 운반한 뒤 복귀하는 과정 확인
5. 완료·취소 작업과 실시간 이벤트 검색
6. LiDAR 센서 상태 및 장애물 위치 확인
7. 위험 상황에서 전체 로봇 비상정지
8. 현장 점검과 운영 승인으로 안전하게 시스템 복구
9. 현재 관제 데이터를 JSON 파일로 백업
10. 개발 테스트용 Mock 데이터 또는 ROS2 DB 초기화
11. 두 로봇의 앞·뒤축 정렬과 네 타이어 지지 상태 확인
12. ArUco 검출·Odom 융합·정렬 결과 확인

전체 연결 관계를 간단히 표현하면 다음과 같습니다.

```text
사용자
  ↓ 입차·출차 요청
웹 UI
  ↓ REST API
FastAPI 서버
  ├─ Mock 모드: 메모리 안에서 로봇 이동을 자동 시뮬레이션
  └─ ROS2 모드: task_dispatcher 서비스로 작업 전달
                     ↓
                 로봇 2대 편성
                     ↓
                입차 또는 출차
                     ↓
          DB·ROS2 상태를 웹 화면에 표시
```

## 2. 로봇 4대는 어떻게 나뉘나요?

차량 한 대를 로봇 두 대가 한 팀으로 들어서 운반합니다.

| 화면 표시 | 내부 로봇 ID | 역할 |
|---|---|---|
| 입차 L | `entry_lead` | 입차 팀 리더 |
| 입차 F | `entry_follow` | 입차 팀 팔로워 |
| 출차 L | `exit_lead` | 출차 팀 리더 |
| 출차 F | `exit_follow` | 출차 팀 팔로워 |

- **리더(Lead)**: 이동 방향과 작업을 대표하는 로봇입니다.
- **팔로워(Follow)**: 리더와 간격을 유지하며 함께 차량을 운반합니다.
- 입차 팀과 출차 팀이 따로 있어 두 종류의 작업을 구분해서 처리합니다.

## 3. 실행 모드 이해하기

웹 UI에는 `Mock`과 `ROS2` 두 가지 실행 모드가 있습니다.

| 구분 | Mock 모드 | ROS2 모드 |
|---|---|---|
| 목적 | 화면과 기능을 간단히 체험 | ROS2·DB와 연결해 통합 테스트 |
| ROS2 설치 | 필요 없음 | 필요 |
| MySQL | 필요 없음 | 필요 |
| 로봇 이동 | 자동 가상 이동 | ROS2 노드 또는 테스트 orchestrator가 처리 |
| 데이터 저장 | 서버 메모리 | MySQL DB |
| 추천 대상 | 웹 UI를 처음 확인하는 사람 | 시스템 통합 테스트 담당자 |

### 3.1 Mock 모드 실행

```bash
cd /home/rokey/Desktop/feature_UI/Rokey_proj_03-Isaac-Sim-/parking_control_mvp
python3 -m pip install -r requirements.txt
PARKING_MODE=mock python3 -m uvicorn main:app --host 127.0.0.1 --port 8000
```

Mock 모드에서는 요청을 등록하면 작업 단계와 로봇 위치가 자동으로 진행됩니다.

### 3.2 ROS2 통합 테스트 모드 실행

> 주의: 다음 테스트 스크립트는 주차면, 로봇 상태, 차량 및 작업 이력을 테스트 초기
> 상태로 되돌립니다. 보존해야 하는 운영 DB에는 사용하면 안 됩니다.

기존에 실행 중인 웹 서버와 ROS2 노드를 각 터미널에서 `Ctrl+C`로 먼저 종료합니다.

```bash

source /opt/ros/humble/setup.bash

export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
unset FASTRTPS_DEFAULT_PROFILES_FILE FASTDDS_DEFAULT_PROFILES_FILE

```

이 스크립트는 다음 구성요소를 한 번에 실행합니다.

- 로봇 4대와 주차면 A1~A3 초기화
- 입차용 가상 orchestrator
- 출차용 가상 orchestrator
- 작업 배정 노드 `task_dispatcher`
- 주차면 관리 노드 `parking_slot_manager`
- 중앙 안전 관리자 `safety_supervisor`
- 웹 UI 서버

터미널에 `준비 완료!`가 나오면 브라우저에서 <http://127.0.0.1:8000>을 엽니다.

## 4. 화면 위쪽 기능

### 비상정지

빨간색 `비상정지` 버튼은 움직이는 모든 로봇을 즉시 정지시키는 안전 기능입니다.

- 진행 중 작업은 취소됩니다.
- 단순히 알림을 지우는 것으로 복구되지 않습니다.
- 현장 점검과 운영 복귀 승인까지 완료해야 새 작업을 받을 수 있습니다.

실제 위험 상황을 가정한 기능이므로 일반적인 정지 버튼처럼 사용하면 안 됩니다.

### 실행 모드 배지

- `Mock Mode`: 웹 서버 내부 시뮬레이션 사용
- `ROS2 Mode`: ROS2 서비스·토픽 및 MySQL 사용

### 시스템 상태

화면 오른쪽 위 상태는 전체 시스템 상태를 요약합니다.

- **정상**: 작업을 받을 수 있는 상태
- **주의 필요**: 로봇 또는 센서 연결 확인 필요
- **시스템 오류**: 비상정지 또는 심각한 오류 발생

LiDAR를 실행하지 않는 가상 입·출차 테스트에서는 센서가 `0/1`로 표시될 수 있습니다.
가상 로봇 입·출차만 시험하는 상황이라면 정상적인 표시입니다.

## 5. `주차장 현황` 탭

주차장과 로봇 상태를 한눈에 보는 기본 화면입니다.

### 요약 카드

화면 위쪽의 네 카드에서 다음 내용을 확인합니다.

| 카드 | 의미 |
|---|---|
| 가용 주차면 | 전체 주차면 중 비어 있는 칸 |
| 작업 현황 | 현재 진행 중인 입·출차 작업 수 |
| 로봇 팀 | 정상 상태인 로봇 수 |
| 센서 | 연결된 LiDAR 센서 수 |

### 실시간 주차장 도면

도면에는 다음 정보가 표시됩니다.

- A1, A2, A3 주차면
- 입차·출차 로봇 대기 구역
- 차량 입차·출차 대기 구역
- 입차·출차 이동 경로
- 로봇 4대의 현재 위치
- 작업 대상 주차면과 진행 경로
- 선택적으로 LiDAR 위치와 감지 영역

주차면 색상의 의미:

- 초록색: 빈 공간
- 주황색: 작업을 위해 예약된 공간
- 보라색: 차량이 주차된 공간

### 항목 상세 보기

도면에서 주차면, 로봇, 작업 또는 장애물 표시를 누르면 오른쪽 상세 영역에서 다음을
확인할 수 있습니다.

- 주차면 상태와 차량번호
- 로봇 상태, 위치, 통신 상태
- 현재 맡은 작업
- 작업 진행 단계
- 장애물 위치와 영향을 받는 로봇
- 안전 사고 진행 상태

오른쪽 패널 상단의 가로 탭은 다음 의미입니다.

| 탭 | 표시 내용 |
|---|---|
| 작업 | 차량번호, 담당 로봇, 작업 단계, 안전 상태 |
| 적재 상태 | 앞·뒤축 정렬 오차, 네 타이어 지지점, 리프트·동기화 상태 |
| 비전 | ArUco 마커 테두리·중심점, 거리, 재투영 오차, 정렬 상태 |

적재 상태 탭은 현재 작업 단계에 맞는 정보만 보여줍니다.

- 차량 접근: 앞·뒤축 정렬 오차와 허용 범위
- 리프트: 네 암의 명령값·실제 관절값과 타이어 지지 추정
- 주차 이동: 차량 Pitch·Roll, 동기화, 미끄러짐·하중 이상 추정
- 복귀: 차량 배치 완료와 로봇 복귀 상태

현재 단계에 필요한 데이터가 전혀 없거나 2초 넘게 끊기면 빈 수치 카드를 반복해서
보이지 않고, `적재 확인 불가 · 제한 정보 표시 중` 안내 하나로 묶어 표시합니다.
데이터 수신이 재개되면 해당 단계의 상세 지표가 자동으로 다시 나타납니다.
작업이 완료되면 담당 로봇의 실제 상태를 기준으로 `대기` 등을 표시하며, 이미 끝난
작업에는 `수신 대기`나 `최근 수신 기록 없음` 같은 실시간 진단 문구를 표시하지 않습니다.
진행 작업이 없으면 지도 상단에 `현재 진행 작업 없음`과 최근 완료 작업을 표시하고,
우측 패널에는 작업 시간·최종 주차면·사용 로봇을 결과 요약으로 보여줍니다.

현재 로봇은 한 대당 암 관절이 4개이므로 두 대를 합하면 총 8개입니다. 화면에서는
운영자가 이해하기 쉽도록 차량의 네 타이어 지지점으로 묶고, 각 지지점에 해당하는 암
관절 2개의 전개율 중 더 낮은 값을 표시합니다. 각 지지점을 누르면 해당 로봇이
메인 지도에서 강조됩니다.

### 실제값과 추정값 구분

- `Mock 시뮬레이션`: 화면 동작 확인을 위해 생성한 테스트값
- `JointState 측정`: Isaac Sim 관절 상태에서 받은 실제 전개율
- `지지 추정`·`적재 안정 추정`: 관절 전개와 동기화 상태로 판단한 값
- `—` 또는 `미측정`: 아직 해당 작업 단계가 아니거나 측정하지 않은 값
- `수신 대기`: 해당 단계에서 데이터가 들어오기를 기다리는 상태
- `미수신`: 리프트·운반 단계에서 받아야 할 데이터가 2초 넘게 오지 않는 상태

값이 없을 때 임의의 정상 수치를 표시하지 않으며, 패널 하단에는 최근 적재 데이터의
수신 경과 시간과 수신률을 함께 표시합니다.

ROS2 모드에서는 다음 토픽을 사용합니다.

```text
/robot_<id>/pose                 ArUco·Odom 융합 로봇 위치
/robot_<id>/axle_center          Depth로 검출한 차축 중심
/robot_<id>/joint_states         암 관절 실제 전개 상태
/robot_<id>/lift_cmd             리프트 전개 명령
/robot_<id>/vision/alignment     ArUco 검출 진단 JSON
```

### 데이터 갱신 주기

- 평상시: 약 2초마다 갱신
- 작업 진행 중: 약 0.25초마다 갱신

로봇 좌표가 바뀌면 화면에서 갑자기 순간이동하지 않고 부드럽게 이동하도록 표시합니다.

## 6. `입·출차 요청` 탭

차량번호를 입력해 새 작업을 등록하는 화면입니다.

### 입차

외부 차량을 빈 주차면으로 옮기는 작업입니다.

```text
요청 접수
→ 가까운 빈 주차면 선택
→ 입차 리더·팔로워 로봇 배정
→ 차량 접근
→ 차량 들어 올림
→ 주차면으로 운반
→ 차량 배치
→ 로봇 대기 장소 복귀
→ 완료
```

### 출차

주차된 차량을 외부 출차 대기 구역으로 옮기는 작업입니다.

출차하려면 같은 차량번호의 **완료된 입차 기록**이 있어야 합니다. 입차 기록이 없는
차량번호를 입력하면 요청이 거절되는 것이 정상입니다.

### 장애물에 따른 요청 제한

입차 통로에만 장애물이 있으면 입차 요청만 차단되고 출차 요청은 계속 받을 수 있습니다.
반대로 출차 통로에만 장애물이 있으면 출차 요청만 차단됩니다.

전체 비상정지 상태에서는 입차와 출차를 모두 등록할 수 없습니다.

## 7. `작업·이벤트` 탭

현재 작업과 과거 기록을 확인하는 화면입니다.

### 작업 상태

| 내부 상태 | 화면에서 이해할 의미 |
|---|---|
| `WAITING` | 요청 대기 |
| `ROBOT_ASSIGNED` | 로봇 할당 |
| `APPROACHING` | 차량 접근 |
| `LIFTING` | 차량 들어 올리는 중 |
| `MOVING_TO_SLOT` | 차량 운반 중 |
| `RETURNING` | 로봇 복귀 중 |
| `COMPLETED` | 작업 완료 |
| `CANCELLED` | 오류 또는 안전 문제로 취소 |

작업을 선택하면 해당 작업과 관련된 이벤트만 따로 볼 수 있습니다.

### 검색과 필터

- 차량번호 검색
- 진행 중/완료/오류·취소 상태 필터
- 입차/출차 유형 필터
- 작업/로봇/센서/안전 이벤트 종류 필터

### 데이터 관리 메뉴

오른쪽 위 `⋮` 메뉴에서 다음 기능을 사용합니다.

- **데이터 백업**: 현재 관제 상태를 JSON 파일로 내려받습니다.
- **Mock 데이터 초기화**: Mock 모드의 요청과 상태를 처음으로 되돌립니다.
- **DB 초기화**: ROS2 테스트 DB의 작업 이력과 테스트 상태를 초기화합니다.

`DB 초기화`는 되돌릴 수 없는 개발용 기능이므로 확인 문구를 정확히 입력해야 실행됩니다.
진행 중 작업이나 비상정지 상태가 있으면 초기화를 거부합니다.

## 8. 알림과 센서 기능

### 알림 종류

- 장애물 감지
- 로봇 오류
- 센서 연결 끊김
- 비상정지 및 안전 복구 상태

알림을 누르면 가능할 경우 도면의 해당 위치와 영향을 받는 로봇을 함께 보여줍니다.

### 센서 알림 숨기기

테스트 중 LiDAR를 일부러 사용하지 않을 때 센서 연결 경고를 화면에서 숨길 수 있습니다.
숨긴 알림은 헤더의 `숨긴 센서 알림 다시 보기` 버튼으로 복원할 수 있습니다.

알림을 숨기는 기능은 화면 표시만 바꾸며 실제 센서 상태를 정상으로 바꾸지 않습니다.

### 센서 영역 보기

`센서 영역 보기` 버튼으로 도면에서 LiDAR 위치와 감시 영역을 표시하거나 숨길 수 있습니다.

---

## 9. 비상정지와 안전 복구

비상정지는 한 번의 클릭으로 해제되지 않도록 두 단계 복구 절차를 사용합니다.

```text
NORMAL
  ↓ 비상정지
STOPPED
  ↓ 현장 점검 완료·해제 요청
RESET_PENDING
  ↓ 별도 운영 복귀 승인
NORMAL
```

### 1단계: 현장 점검·해제 요청

담당자가 다음 내용을 확인합니다.

- 작업 구역에 사람이 없는지
- 모든 로봇이 정지했는지
- 차량과 리프트가 안전하게 지지되는지
- 센서와 통신 상태를 확인했는지

담당자 ID와 점검 내용을 작성하고 모든 확인 항목을 체크해야 합니다.

### 2단계: 운영 복귀 승인

별도의 승인 담당자가 현재 상태를 다시 확인하고 새 작업 접수를 허용합니다.

중요한 동작 원칙:

- 비상정지로 취소된 작업은 자동으로 다시 시작하지 않습니다.
- 복구 완료 후 새 입차·출차 요청을 등록해야 합니다.
- 담당자와 점검 내용은 안전 이력에 남습니다.

## 10. 입차·출차 테스트 순서

### 10.1 입차 테스트

1. `입·출차 요청` 탭을 엽니다.
2. 요청 유형에서 `입차 요청`을 선택합니다.
3. 새 차량번호(예: `1111`)를 입력합니다.
4. `요청 등록`을 누릅니다.
5. `주차장 현황`에서 입차 로봇 2대의 이동을 확인합니다.
6. `작업·이벤트`에서 상태가 `완료`로 바뀌는지 확인합니다.
7. A1~A3 중 한 칸이 `주차 중`으로 바뀌는지 확인합니다.

### 10.2 출차 테스트

1. 앞의 입차 작업이 완전히 완료될 때까지 기다립니다.
2. 요청 유형에서 `출차 요청`을 선택합니다.
3. 입차 때 사용한 차량번호 `1111`을 다시 입력합니다.
4. `요청 등록`을 누릅니다.
5. 출차 로봇 2대가 해당 주차면으로 이동하는지 확인합니다.
6. 작업 완료 후 해당 주차면이 다시 `빈 공간`이 되는지 확인합니다.

## 11. 자주 발생하는 문제

### 웹 페이지가 열리지 않아요

웹 서버가 실행 중인지 확인합니다.

```bash
curl http://127.0.0.1:8000/api/system
```

### 예전 화면이 보여요

브라우저에서 `Ctrl+Shift+R`을 눌러 강력 새로고침합니다.

### `dispatch_parking_task`에 연결할 수 없다고 나와요

웹 UI와 ROS2 노드의 `ROS_DOMAIN_ID`가 같은지 확인합니다.

```bash
echo "$ROS_DOMAIN_ID"
ros2 service list | grep dispatch_parking_task
```

정상이라면 다음 서비스가 표시됩니다.

```text
/dispatch_parking_task
```

### 요청 직후 작업이 취소돼요

실행 로그에서 실제 원인을 확인합니다.

```bash
find /tmp -maxdepth 1 -type d -name 'parking_test_stack.*'
tail -n 100 /tmp/parking_test_stack.*/entry_orch.log
tail -n 100 /tmp/parking_test_stack.*/exit_orch.log
tail -n 100 /tmp/parking_test_stack.*/disp.log
```

기존 DB에 `robots.target_node` 컬럼이 없어서 취소되는 문제는 현재
`run_test_stack.sh`가 시작할 때 자동으로 마이그레이션하도록 수정되어 있습니다.

### 로봇이 0/4로 보여요

로봇 4대가 DB에 등록되었는지 확인합니다.

```bash
mysql -u parking -pparking1234 parking \
  -e "SELECT robot_id,status,x,y FROM robots;"
```

### 출차 요청이 거절돼요

출차는 같은 차량번호로 완료된 입차 기록이 있어야 합니다. 먼저 입차 작업이
`완료`됐는지 확인합니다.

### 센서가 0/1로 보여요

LiDAR publisher가 실행되지 않았다는 의미입니다. 가상 입·출차 테스트에서는 로봇 동작과
별개이므로 센서 제한 상태로 테스트할 수 있습니다. 실제 안전 감지 테스트에서는 반드시
LiDAR와 관련 relay를 실행해야 합니다.

## 12. 주요 API

API를 직접 사용할 필요는 없지만, 화면 뒤에서 어떤 기능이 호출되는지 이해하는 데
도움이 됩니다.

| 방식 | 주소 | 기능 |
|---|---|---|
| GET | `/api/system` | 모드와 전체 시스템 상태 조회 |
| GET | `/api/dashboard` | 로봇·주차면·작업·알림 통합 조회 |
| POST | `/api/requests` | 입차·출차 요청 등록 |
| POST | `/api/alerts/{id}/resolve` | 일반 알림 해제 |
| POST | `/api/emergency-stop` | 전체 비상정지 |
| POST | `/api/safety/reset-request` | 현장 점검 및 해제 요청 |
| POST | `/api/safety/approve-operation` | 운영 복귀 승인 |
| POST | `/api/reset` | Mock 데이터 초기화 |
| POST | `/api/mock/obstacle` | Mock 장애물 이벤트 발생 |
| POST | `/api/mock/robot-error` | Mock 로봇 오류 이벤트 발생 |
| POST | `/api/ros2/db-reset` | ROS2 테스트 DB 초기화 |

FastAPI가 자동 생성하는 API 문서는 <http://127.0.0.1:8000/docs>에서 직접 시험할 수
있습니다.

## 13. 코드 구조를 아주 간단히 이해하기

| 파일·폴더 | 역할 |
|---|---|
| `main.py` | 웹 주소와 API 요청을 연결 |

모드에 함께 반영됩니다.

## 14. 용어 풀이

- **관제**: 로봇과 주차장의 상태를 한곳에서 확인하고 명령하는 것
- **주차면/슬롯**: 차량이 주차되는 A1, A2, A3 공간
- **ROS2**: 로봇 프로그램들이 서비스와 토픽으로 통신하는 시스템
- **서비스**: 요청을 보내고 응답을 받는 ROS2 통신 방식
- **토픽**: 센서나 작업 상태를 계속 전달하는 ROS2 통신 방식
- **dispatcher**: 요청에 맞는 주차면과 로봇을 배정하는 프로그램
- **orchestrator**: 배정받은 로봇 작업 순서를 실제로 진행하는 프로그램
- **Mock**: 실제 장비 없이 동작을 흉내 내는 테스트 방식
- **LiDAR**: 레이저로 주변 장애물과 거리를 감지하는 센서
- **DB**: 로봇, 차량, 주차면, 작업 기록을 저장하는 데이터베이스
